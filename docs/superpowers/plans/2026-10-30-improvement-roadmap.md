## 方針

1. **安全 → 再現性 → 分離（保守性）の順。** ただし全項目をこの順に直列化はしない。反例テストと、安全層に触れない文書・CI の是正は並行して進める。
2. **安全層の変更は人の決定が要る。** `src/devices/safety/` を編集する項目は本書で明示する（0-6、1a、1b、1c、1f、1g、1h、3h、W3、W4）。反例テストを先に置き、人が「直す」と決めてから実装する。AI は限界を緩めない。
3. **反例を先にテストにする。** 実機ラッパーと mock は同じ構造を共有しているので、mock との一致テストでは検出できない。制約そのものに対する反例を、両方に独立に置く。実機ラッパーは fake controller が記録した**送信列**で、mock は**状態が変わらないこと**で確かめる。本書の「送信 0 件」は**状態を変える指令が 0 件**の意味で、姿勢などの状態照会は数えない（slider の事前検査のように、検査そのものに姿勢の読出しが要るため）。
4. **検証したものを送る。** 安全検査は、装置へ送る具体的な値に対して行う。検証の後で下位の層が状態を読み直して目標を計算し直す経路を残さない（1a・C6）。
5. **拒否と故障を例外の型で分け、拒否は副作用の前に置く。** 「送信前に検証で拒否した」ことと「送信後に装置が失敗した」ことは復帰の扱いが違う。前者で復帰動作を走らせてはならない（C1）。
6. **予測は実測の代わりにならない。** preflight の姿勢推定は補助であり、実行時の実測姿勢に対する検査を省く根拠にしない。
7. **実機での確認は人の作業。** 回転の経路や停止の挙動はコードから導いた推論であって実測ではない。Phase 1 の受入には bench での確認が要る。

天秤ごとの状態:

| 状態 | 意味 | 更新する事象 |
|---|---|---|
| `tared` | このランで tare したか | tare で真 |
| `baseline` | `since_previous` の基準の値。tare の直後は 0、計量が成功するとその値、最初は無し | tare、成功した計量 |
| `pending` | 前回の成功した計量または tare の後の分注の数と期待量 | dispense で加算。成功した計量と tare で 0 に戻す |
| `since_tare` | tare の後の分注の数 | dispense で加算。tare で 0 に戻す |
| `tainted` | 分注が不完全で、次の tare まで誤差を出さない | 不完全な分注と blow_out で真。tare で偽 |

分注の完了の判定: 例外なく終わった dispense は、Picus2 のように「書込み完了」かつ公称時間の待機でも**完了**として扱う。write の中断・応答の喪失・例外・キャンセル（C1 の「結果不明」か未完了）は**不完全**とする。

blow_out の判定（`LabRobot.blow_out` は残液をすべて排出する、`lab_robot.py:853`）: 同じロボットの dispense の直後（間に tare も計量も他のロボットの操作も無い）で、排出する保持量が 0 mL のとき（残滴の除去）だけ、直前の dispense の一部として状態を変えない。保持量が 0 より大きい、別のロボットの blow_out、直前が dispense でない、保持量が不明、blow_out の失敗・中断は、すべて `tainted` を真にする（排出量と投入先が分からない）。

## 進め方の規約（全フェーズ共通）

- 1 項目 = 1 ブランチまたは 1 連のコミット。失敗するテストを先に書き、RED を見てから実装（TDD）。安全の反例テストは「拒否された」でなく「送信された指令列」を assert する。
- 完了報告の前に `python -m pytest tests/ src/monitoring/tests/ src/imaging/tests/ -q` と、0-9 の表どおりの `--validate-only` / `--mock` を実行する。
- `src/devices/safety/` を編集する項目（0-6、1a、1b、1c、1f、1g、1h、3h、W3、W4）は着手前に人の承認を得る。limits を緩める方向の変更は一切行わない。拒否が増える変更は CHANGELOG と README に明記する。
- 新しい拒否は必ず `ValidationError` の派生で投げ、副作用の前に置く（C1）。
- 実機を動かす確認（1a の回転・go_home・`move_z` の送信値、1b の Stop）は人が行い、結果を `docs/*-commissioning.md` に書く。AI は `--mock` までで止まる。
- 各項目の実装手順書は着手時に `docs/superpowers/plans/YYYY-MM-DD-<id>-<slug>.md` として書く。共通契約 C1〜C7 は `docs/superpowers/specs/YYYY-MM-DD-<id>-<slug>.md` に 1 件 1 ファイル。
